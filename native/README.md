# Limochat — Android и Windows

Версия 1.1: Android использует Trusted Web Activity в поддерживаемом браузере; Windows остаётся изолированным Electron-клиентом. Оба приложения открывают `https://81-90-31-167.sslip.io/` в отдельном окне и используют существующие аккаунты, чаты и настройки. Сервер должен быть доступен. Обновления интерфейса приходят с сайта; изменения нативной оболочки требуют новой установки.

## Скачать сборки

В GitHub откройте **Actions → Build APK and EXE → успешный запуск → Artifacts**.
- `Limochat-Android-APK`: ZIP с `Limochat-Android-test.apk`, Android 10+.
- `Limochat-Windows-EXE`: ZIP с установщиком `Limochat-Setup-1.1.0-x64.exe`, Windows 10/11 x64.

APK — тестовый, подписан стандартным debug-ключом сборочной машины. Это отдельное приложение `io.limochat.app.browser`, поэтому оно не заменяет старые неизвестные APK. Для обновляемых production-сборок нужен собственный постоянный закрытый ключ; его нельзя публиковать в репозитории. Windows-сборка без подписи издателя: Windows может показать предупреждение о неизвестном издателе.

## Что поддерживается

- Сохранение входа между запусками.
- Android: выбор файлов, скачивание в «Загрузки», системные запросы камеры, микрофона и геолокации, полноэкранное видео, кнопка «Назад», экран повтора при сетевой ошибке.
- Windows: отдельное окно, сохранение размера, масштабирование, камера/микрофон по запросу, выбор экрана для демонстрации.
- Внешние ссылки открываются в браузере; сайт не получает доступ к Node.js и файловой системе.

Это онлайн-клиенты, а не автономные серверы. В Android Web Push обслуживается браузером: включите его в настройках Limochat и разрешите уведомления в Android. Для работы нужен поддерживаемый обновлённый браузер (например, Chrome). Содержимое сайта и браузерные функции совпадают; неподдерживаемые самим браузером возможности не появляются автоматически. Активный WebRTC-звонок в фоне и доставка на конкретном телефоне требуют проверки на устройстве. Windows продолжает работать в трее при закрытии окна; полный выход прекращает уведомления. Вход и чаты Android берутся из сессии браузера, а не прежней WebView-оболочки.

## Сборка

Android: JDK 17, Gradle 8.13, Android SDK 36, затем `cd native/android && gradle :app:assembleDebug`. Иконка копируется из `public/icons/icon-192.png` задачей Gradle.

Windows: Node.js 22, `cd native/desktop && npm install && npm run dist`. Создайте `native/desktop/icon.ico` из PNG перед сборкой (команда есть в workflow). Версии Electron и electron-builder закреплены в package.json. CI проверяет создание изолированного окна перед упаковкой.

Документация: [Android Gradle 8.7](https://developer.android.com/build/releases/agp-8-7-0-release-notes), [безопасность Electron](https://www.electronjs.org/docs/latest/tutorial/security).

Для полноэкранного TWA нужно опубликовать `assetlinks.generated.json` из артефакта на `/.well-known/assetlinks.json`. Файл содержит публичный отпечаток сертификата конкретного APK. Если проверка не пройдена, браузер покажет верхнюю адресную панель. Это нормально для тестовой сборки с другим сертификатом; приватный ключ здесь не публикуется. Новая Android-сборка устанавливается отдельно от прежнего WebView-теста.
